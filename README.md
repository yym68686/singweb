# singweb

singweb 是管理多台设备上 sing-box 的面板。每个分组对应设备上的一个 selector，设置它接管哪些流量、可以选用哪些节点、怎样选择节点。按规则自动切换的分组由设备上的 Agent 经由每个节点探测分组规则，当前节点连续未通过时自动切换；候选节点全部不可用时按设置阻断并告警，不会悄悄改走直连。

仓库里有四部分：前端、管理服务、设备上的 Agent，以及三者共用的代码。都是 TypeScript，Node.js 24 直接执行，没有编译步骤。

## 工作方式

```text
浏览器（本仓库）
    │  REST + SSE，接口见 docs/api.md
管理服务：保存配置，汇总各设备的状态和事件
    │
每台设备上的 Agent（macOS、Linux）
    ├─ 经由每个节点探测分组规则引用的目标：SSH 服务、网址或 TCP 端口
    └─ 通过 sing-box 的 Clash API 切换 selector
```

- **分组**：设备上的一个 selector。它接管的流量可以按域名、IP 段、规则集、协议、端口或进程划分；候选节点可以逐个挑选，也可以按地区、协议和名称自动加入，订阅里新增的节点符合条件就自动进组。
- **分组规则**：按规则自动切换的分组用一条或多条规则判断节点能不能用，可以要求全部通过或任意一条通过。每条规则引用一个探测目标：
  - SSH 探测：读到 SSH 标识或完成握手，可以核对主机密钥。
  - HTTP 探测：检查状态码和响应内容，能发现被网站拒绝的节点，比如某些地区请求 OpenAI 接口时返回 403。
  - TCP 探测：只检查能否连上目标端口，适合数据库、远程桌面这类服务。
- **手动选择**：分组也可以不探测、不自动切换，在设备页手动选择节点，和普通的 selector 一样。

Agent 的具体做法：

- **探测结果按“设备、节点、目标”三层记录。** 探测在设备本地进行，同一个节点在不同设备上的结果可能不一样。
- **通过探测不代表能登录。** 探测不发送账号、密钥或任何凭据：SSH 探测最多做到握手，HTTP 探测只看状态码和响应内容。
- **不因一次失败切换。** 节点连续几轮未通过才判为不可用（默认 3 轮），不可用的节点连续几轮通过才重新可用（默认 2 轮），轮数在分组里设置。当前节点可用时保持不动。
- **全部不可用时明确处理。** 默认阻断这个分组的新连接，并记一条严重事件；也可以保持当前节点，或者明确选择改走直连。
- **切换只影响新连接。** 已经打开的长连接（比如 SSH 会话、WebSocket）要断开重连才会走新节点，除非分组打开了“切换时断开已有连接”。
- **设备和管理服务断开时，Agent 照常工作。** 它按最后收到的分组、固定的节点和手动选择的节点在本地探测和切换，重新连上后再同步。

## 页面

| 页面 | 地址 | 内容 |
| --- | --- | --- |
| 总览 | `/` | 需要注意的问题、各设备各分组的当前出口、最近事件 |
| 设备 | `/devices`、`/devices/:id` | 每台设备上各分组的状态和候选节点、固定节点或手动选择节点、sing-box 配置片段 |
| 连通性 | `/matrix` | 每台设备经由每个节点探测每个目标的结果，可以按设备或按目标查看 |
| 事件 | `/events` | 什么时候、为什么、从哪个节点切到哪个节点；可以按设备、分组、类型和级别筛选 |
| 分组 | `/groups`、`/groups/new`、`/groups/:id` | 接管哪些流量、候选节点、选择方式和分组规则、切换设置、全部不可用时怎么办 |
| 探测目标 | `/targets` | 分组规则用到的 SSH 服务、网址和 TCP 端口，以及怎样算通过 |
| 节点 | `/nodes` | sing-box 里的代理出站，停用后不参与任何分组 |

界面是中文的，有浅色和深色两种外观，最窄适配 320 px 宽的屏幕。

## 开发

需要 Node.js 20.19 或 22.12 以上的版本。

```bash
npm install
npm run dev         # 开发服务器，http://localhost:5173
npm run typecheck   # 类型检查
npm run build       # 类型检查，然后构建到 dist/
npm run preview     # 在本地预览构建结果
```

`dist/` 里是静态文件，可以放在任何静态服务器上，也可以由管理服务直接提供。页面使用浏览器路由，服务器要把找不到的路径都回退到 `index.html`。

## 配置

把 `.env.example` 复制成 `.env` 再修改：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `VITE_API_BASE` | `/api/v1` | 接口前缀 |
| `SINGWEB_API_PROXY` | 不转发 | 只在 `npm run dev` 时使用，把 `/api` 转发到管理服务，例如 `http://127.0.0.1:8080` |
| `PORT` | `8080` | 管理服务监听的端口 |
| `HOST` | `0.0.0.0` | 管理服务监听的地址 |
| `DATABASE_URL` | `postgres://localhost:5432/singweb` | 数据库连接串 |
| `DATABASE_SSL` | 关 | 托管数据库要求 TLS 时设为 `1` |
| `STATIC_DIR` | 仓库根的 `dist` | 前端构建产物目录 |

`VITE_` 开头的变量在构建时写进代码，修改后要重新构建。

订阅链接不在这里配置。它在数据库里，由网页的「订阅」页面录入。拉订阅、解析节点都由服务端自己做，设备只从服务端拿整理好的节点，见不到订阅链接；链接也不进仓库、不进日志。

## 部署

### Docker Compose

一条命令把管理服务和 PostgreSQL 一起跑起来：

```bash
POSTGRES_PASSWORD=改成你自己的密码 docker compose up -d
```

打开 `http://localhost:8080`。首次启动时数据库还是空的，服务端会建好表并创建第一个账号，用户名 `admin`、密码随机生成，**只打印一次在启动日志里**：

```bash
docker compose logs app | grep -A2 已经建好
```

登录后请尽快改掉密码。

同一次启动还会建好两样东西，方便上手：

- 探测目标「GitHub SSH」：`ssh.github.com:443`，banner 级别。走 443 是 GitHub 专门给 22 端口不通的网络准备的，能探通的节点基本就是真能连外网 SSH 的节点。
- 分组「SSH 出口」：接管本机发往 22 / 2222 端口和嗅探为 SSH 的流量，拿上面那个目标探测，按延迟选节点，全都探不通时保持当前节点。候选是节点池里的全部节点——能不能进这个分组由探测结果决定，所以新订阅里的节点会自动参与，探不通的自然被排除。
- 分组「全部节点」：手动选择，把节点池全兜住，手机上只能导入链接的客户端用它。

这三样都只在库里还没有同名条目时才建。建成之后服务端不再插手：改了名称、换了规则、整个删掉，重启都不会被变回来。

### 不用容器

需要 Node.js 24（直接执行 TypeScript）和一个能连的 PostgreSQL：

```bash
npm install
npm run build
DATABASE_URL=postgres://用户:密码@主机:5432/singweb PORT=8080 node server/src/index.ts
```

表结构在 `server/schema.sql`，启动时自动执行，都是 `create ... if not exists`，重复跑没有影响。服务端自己不保存状态，进程随时可以重启——所有东西都在数据库里，多实例部署也不需要共享内存。

### 接入设备

管理员在设备页点「接入新设备」，把 macOS 或 Windows 的那一行命令复制到设备上运行。脚本会：

- 找够新的 Node.js 和 sing-box，没有就下载到 `~/.singweb`；
- 下载 Agent，用命令里的一次性令牌接入；
- 设成登录后自动运行。

全程不需要管理员权限。运行前设 `SINGWEB_NO_SERVICE=1`，就不设自动运行，只在当前终端前台跑。

也可以手动接入，需要 Node.js 24 和 sing-box：

```bash
node agent/src/bin.ts join --server https://你的域名 --token <注册令牌>
node agent/src/bin.ts run
```

Agent 主动向管理服务上报，管理服务不会反向连设备，所以设备在内网、没有公网地址也能接进来。Agent 的接入信息存在 `~/.singweb/agent.json`，权限是 600。

## 目录

```text
src/            前端（Vite + React）
  api/          数据类型、HTTP 客户端
  app/          外壳：导航、登录检查、外观切换
  components/   通用组件
  lib/          文案、格式化、候选节点筛选、sing-box 配置片段生成
  pages/        各页面
server/         管理服务（Node + PostgreSQL）
  schema.sql    库结构
  src/routes/   接口：web 给浏览器，agent 给设备
agent/          设备上的 Agent：生成本机 sing-box 配置、探测、切 selector
shared/         前后端和 Agent 共用的代码：类型、筛选、sing-box 片段、订阅解析、运行状态推导
docs/api.md     前端、管理服务和 Agent 之间的接口约定
Dockerfile      单进程同时发前端和接口
docker-compose.yml
```
